# Versión HTML standalone (100% online, sin servidor propio) Un solo archivo (`index.html`) que se conecta directo a tu Supabase real desde el navegador — sin Next.js, sin `npm install`, sin servidor propio que mantener. Lo abres, o lo subes a cualquier hosting estático (GitHub Pages, Netlify, Vercel, o incluso solo abrir el archivo local), y funciona con datos reales. ## Qué incluye - Login por usuario + contraseña - Diario: lista de la semana + formulario estructurado (entrada/salida, con auto-relleno de formato para syrops) - Producción: cámara/salón, nueva mezcla, traslado a salón, cola de "próximo sabor" - Resumen: tarjetas y tabla matriz (toggle) - Global: 3 láminas con los colores de alerta - Validación de turno para Mateo y Bárbara (bloquea si es su día libre o no tienen horario asignado hoy) ## Qué NO incluye (y por qué) - **Chat de lenguaje natural**: necesita la API key de Anthropic, que nunca debe viajar dentro de un HTML público — cualquiera que abra el archivo podría copiarla. Esa función vive en la versión Next.js (`/control-existencias-web`), donde la key queda protegida en el servidor. - **Edición de rangos de alerta en Configuración**: por ahora de solo lectura en esta versión; se edita desde la versión Next.js. ## 1. Ejecutar el SQL actualizado Este archivo depende de políticas de seguridad (RLS) que no existían en la primera versión del schema, porque aquí no hay ningún servidor de por medio validando permisos — la propia base de datos tiene que rechazar escrituras no autorizadas. **Ejecuta el `supabase_schema.sql` actualizado (o al menos la sección nueva al final, desde `LOGIN POR USERNAME`) en el SQL Editor de Supabase**, aunque ya hayas corrido una versión anterior. ## 2. Configurar tus credenciales Abre `index.html` y edita estas dos líneas cerca del inicio del ``: ```js window.SUPABASE_URL = 'https://TUPROYECTO.supabase.co'; window.SUPABASE_ANON_KEY = 'TU_ANON_KEY'; ``` La `anon key` es segura para exponer en el navegador — está diseñada para eso. Las políticas RLS que ejecutaste en el paso 1 son las que realmente protegen los datos, no el secreto de esta llave. ## 3. Crear tus usuarios Igual que en la versión Next.js: crea la cuenta en Supabase → Authentication → Users, copia el UUID, y luego: ```sql insert into usuarios_bot (correo, username, auth_user_id, nombre, rol, requiere_cierre_turno, dias_libres) values ('tu_correo@ejemplo.com', 'mateo', 'EL_UUID', 'Mateo', 'admin', true, '{DOMINGO}'); ``` ## 4. Usarlo Simplemente abre `index.html` en el navegador (doble clic funciona, o súbelo a cualquier hosting estático). Como todo el dato vive en Supabase, cualquier persona que abra el archivo con sus propias credenciales ve la información real y actualizada — no hay nada "local". ## 5. Dónde alojarlo para que todos lo usen sin instalar nada La forma más simple y gratuita: **GitHub Pages**. 1. Sube este archivo a tu repositorio de GitHub (ya está listo en `/html-standalone`) 2. En GitHub → Settings → Pages, elige la rama `main` y la carpeta `/html-standalone` 3. GitHub te da una URL pública (ej. `https://tuusuario.github.io/control-existencias-producciones/`) — esa es la que le compartes a Bárbara, Victor y Nayareth
